# Processing and project contract

## Processes and security

The renderer is React/TypeScript in a sandboxed Electron renderer with context isolation enabled and Node integration disabled. `preload.cjs` exposes named operations only: picker/drop import, frame, mask, preview, export picker, project picker, diagnostics, explicit weight download, cancellation. IPC checks the sender/main frame. Project JSON is schema-checked; source paths must be imported, loaded or relinked before processing. Renderer media URLs use opaque per-session capability tokens. There is no generic file read, shell command, unrestricted backend HTTP endpoint or Electron remote module. New windows/navigation are blocked. Content Security Policy permits local app assets and local media only; Vite development additionally uses localhost WebSocket.

Electron spawns a one-request Python worker using an argument array and `shell:false`. The project is JSON on stdin, never interpolated into a command. Python likewise calls FFmpeg with argument lists. A worker is exclusive; progress uses JSON lines. Cancellation writes an app-owned marker; Python checks it between operations/frames and while waiting for subprocesses, killing its own active FFmpeg process. There is no server or public listening port in production.

## Timeline / VFR / mask alignment

`ffprobe` reads source metadata. The processing rate is `min(30, max(1, avg_frame_rate))`; invalid/unknown rates fall back to nominal rate or 30. Every selected segment has one explicit constant-rate timeline. FFmpeg applies trim → PTS reset → `fps` with `start_time=0` → square-pixel, even-dimension scaling without enlarging the stored source dimensions. VFR source frames are duplicated/dropped by FFmpeg's fps filter. This deliberately normalizes VFR rather than treating packet numbers as frame indices.

The normalized output duration is `N / fps`, where `N` is at most `ceil((end-start)*fps)`, limited by the actual decoded frame count. Duration quantization is at most one output frame. Frame `n` has output PTS `n/fps`, referenced to source trim start. FFmpeg's sampling/rounding decides the decoded source image associated with that CFR timestamp. No packet-index approximation is used by SAM or the compositor. Non-square pixels are normalized to square pixels while preserving display aspect ratio; auto-rotation is handled by FFmpeg. Even rounding can change an edge by a pixel.

The full source playback proxy normalizes the whole source to CFR for lightweight viewing; at arbitrary trim boundaries it is only a navigation aid. **Frame-step and Mask / correction decode the selected segment's exact normalized frames.** Rendered preview and export always read that same selected-segment frame cache.

Prompts are `{frame, x, y, label}` where frame is **zero-based relative to the selected normalized segment**, x/y are normalized `[0,1]` coordinates inside the displayed picture (no letterbox), and label is 1/include or 0/exclude. SAM reads sequential JPEG copies of those exact cached PNG frames, resized with aspect ratio preserved to at most 640 pixels. It internally uses a 512² inference canvas through the supported `image_size` config override. Returned mask logits are thresholded at zero and stored as grayscale PNGs in the inference frame's dimensions. The compositor resizes alpha back to its original-frame dimensions (or preview size) using bilinear sampling. This maps normalized subject positions back to the original image; it does not regenerate RGB pixels. Mask holes and disconnected regions remain separate; there is no connected-component simplification. Feather/expand/shrink are postprocessing, measured at 1080 vertical pixels and scaled to output height.

The earliest frame with a positive prompt seeds the object. Initial tracking runs forward and backward so every frame is covered. Other prompted frames then correct the established track, including negative-only correction frames. Corrected frames are retained as conditioning frames; propagation runs again across the segment. The worker commits a mask cache only if all frame indices are present. Real-model behavior/quality and reduced-resolution accuracy still need validation with official weights and representative footage.

## Cache and composition

A source cache key includes resolved source path, byte size, modification time and probed metadata. A segment key adds trim, processing rate and pipeline version. A mask key adds prompts plus the model/adapter revision; effects are excluded. Project JSON stores a cache reference for portability/diagnosis, but the worker derives trusted cache paths itself. If caches are absent it regenerates them; clicking Mask Subject on an existing valid cache returns immediately. Editing effects does not import, load or invoke SAM. Caches live under Electron userData/cache and remain on disk until manually removed. No cache eviction UI is provided.

For echo `k`, source index is `n-k*delay`. If it is negative the copy is omitted. The image AND alpha come from that same source index. Copies are drawn farthest first; the current masked subject is optionally pasted above all trails. Translation crops at boundaries and never wraps. Scale is about the frame center plus the requested offset. Tint blends 40% tint into copied RGB. Alpha uses opacity × falloff^(k−1). Grain seeds use rounded microsecond output PTS; a shared 320×180 noise grid is resized for preview/export. Scanlines, RGB offset, color bleed, vignette and rounded borders use normalized positions. Integer pixel rounding and resampling can produce small resolution-dependent differences, but the algorithm/settings/frame identities are shared.

Rendering is disk-backed and sequential. The same `compose()` function serves both output sizes. Preview is ≤640×360, export uses the cached source resolution without upscaling. Finished frame PNGs are encoded to H.264 yuv420p. If audio exists, FFmpeg seeks the original audio to trim start, preserves its relative timing, resamples to an audio clock starting at zero, pads if needed, and trims to `N/fps`; AAC is muxed into MP4. Silent clips skip the audio input/map entirely. Frame and audio timebases are explicitly bounded by the same output duration. Existing exports and original media cannot be overwritten. Partial encoding/composition files are removed on cooperative cancellation; finished caches remain useful.

## Project format

Version 1 JSON contains `version`, absolute `source` reference, `trim`, `prompts`, `maskCache` reference (optional), `effects`, and `export.crf`. It embeds no video or weights. Loading a source that moved displays Relink. Relinking retains prompts/settings; source identity changes invalidate caches. The user must relink to the same footage for those prompts to remain semantically correct. Project paths are local-machine references, not self-contained archives.

## Model choice and verified upstream facts

SAM 2.1 Tiny was chosen over image-only SAM because its documented video predictor supports interactive positive/negative points, persistent temporal state and correction/repropagation. Tiny is the smallest official SAM 2.1 checkpoint (38.9M parameters); upstream performance numbers were measured on A100 and are not RTX 2070 guarantees. Official source inspected during implementation: README, LICENSE, setup.py, build_sam.py, sam2_video_predictor.py, SAM2Base and the Tiny YAML at commit `2b90b9f5ceec907a1c18123530e92e794ad901a4`. Minimum software versions and Windows/WSL guidance are in WINDOWS.md. No reliable RTX 2070 minimum-VRAM or real-time claim was found; actual CUDA/GPU/VRAM are detected instead. Model and GPU quality/performance testing remain outstanding.
